<Aside type="caution" title="Early access">
There's no official mod API yet, so the mod hooks into the game itself, and a game update can break it until a new release catches up. Deleting `override.cfg` from the game folder always turns it off.
</Aside>

## Install

<Tabs syncKey="install">
  <TabItem label="From GitHub">

<Steps>

1. **Make a scripts folder and install the mod.**

   <Install />

   - `bun add` installs the client package, pinned to a release.
   - `bunx melvor2 install` downloads the mod files of that same version from the GitHub release. It puts them in `%APPDATA%\Games By Malcs\Melvor Idle 2\melvor-script\` and adds one file next to `Melvor2.exe`: `override.cfg`, which tells the game to load the mod.
   - `bunx melvor2 init` adds `scripts/hello.ts`, a `tsconfig.json` and VS Code's F5 setup. It never overwrites a file.

2. **Restart Melvor Idle 2** and load a save. On its first start with the mod, the game writes `~/.melvor2-scripting/config.json`, the token your scripts connect with.

3. **Check it's there:** `bunx melvor2 status` prints the mod and game versions.

4. **Run a script:** `bun scripts/hello.ts`, or open it in VS Code and press **F5** (with the Bun extension, `oven.bun-vscode`). It only reads, so it's safe any time.

</Steps>

  </TabItem>
  <TabItem label="From source">

Building the mod needs the [.NET 10 SDK](https://dotnet.microsoft.com/download) and a mingw **clang** (`winget install MartinStorsjo.LLVM-MinGW.UCRT`), and compiles against your installed game.

<Steps>

1. **Clone and build.**

   ```sh frame="terminal" title="Terminal"
   git clone https://github.com/c3d-gg/melvor2-script
   cd melvor2-script
   bun install
   bun run build
   bun run install-mod
   ```

   `build` compiles the native bridge and the C# runtime into `dist/`; `install-mod` copies them into the game's user folder and adds `override.cfg`.

2. **Restart Melvor Idle 2** and load a save.

3. **Check and run:** `bun run melvor2 status`, then `bun examples/hello.ts`. Put your own scripts in `scripts/` (gitignored).

</Steps>

`bun run dev` rebuilds, reinstalls and hot-reloads the runtime into the running game, no restart needed.

  </TabItem>
</Tabs>

**Turn it off:** delete `override.cfg` from the game folder. **Remove it:** `bunx melvor2 uninstall`. **Upgrade** a scripts folder to the version on this site:

## Your first script

Real time is the default: start an action and the game repeats it on its own, exactly as if you'd clicked. Your script decides what to do; the game decides how fast.

<Snippet file="site/snippets/start/real-time.ts" title="scripts/logs.ts" />

`m.count()`, `m.skills.woodcutting.level` and the rest read a live copy of the game, so they need no `await`. When the script ends, the character keeps doing its last action: it's an idle game.

## Scripted Mode, in two styles

In **Scripted Mode** every action happens the moment your script asks: one swing, one catch, one crafting step. Then a cooldown runs, the action's normal time divided by a speed you pick. Nothing repeats on its own, so it plays like a programming game. Turn it on for the loaded save:

```sh frame="terminal" title="Terminal"
bunx melvor2 scripted on
bunx melvor2 speed 50   # optional: the default is 10, up to 1000
```

## The CLI

`bunx melvor2` (or `bun run melvor2` in a clone) prints its commands. The ones you'll use most:

| Command | |
| --- | --- |
| `status` | The mod and game versions, and which screen the game is on |
| `scripted on` / `scripted off` | Scripted Mode for the loaded save |
| `speed 50` | The Scripted Mode speed |
| `recipes Woodcutting` | What a skill can do, with what's unlocked |
| `watch` | Print events as they happen |

The [CLI reference](/reference/cli/) has the rest.
